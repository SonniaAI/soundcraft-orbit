# Lens Studio assembly & preview plan (Snap Spectacles)

Lens Studio is a desktop authoring app (Windows/macOS); company build nodes are
Linux/arm64 and cannot run it. This project therefore ships **complete Lens
project sources** — scripts implementing the full IA geometry plus a
declarative scene manifest — and this guide, so the Lens assembles in
Lens Studio in about 10 minutes. The web companion (`web/`) renders the same
geometry and serves as the geometric preview of record until the Lens preview
is captured.

> Hackathon note (Devpost Learn "AR with SPECS"): the challenge format expects
> an AI coding agent to build the Lens. Feed the agent this directory
> (`lens/`) + `docs/AR-INFORMATION-ARCHITECTURE.md` — the scripts, the scene
> manifest, and the data URL are everything it needs.

## 0. Prerequisites

- Lens Studio 5.10+ with Spectacles support (https://ar.snap.com/download)
- This repo cloned locally
- The web companion reachable at a public URL (GitHub Pages serves it) —
  the Lens fetches `data/session.json` from there

## 1. Create the project

1. Lens Studio → **New Project** → *Spectacles* template.
2. Import `lens/Scripts/*.ts` (drag the folder into the **Assets** panel).
3. Create three empty SceneObjects under a root named `Orbit Stage`:
   `Ring`, `Cards`, `Plaque` (see `orbit-scene.manifest.json`).

## 2. Materials

| Name | Pass settings | Used for |
| --- | --- | --- |
| `seg` | Unlit, Opaque, Double-Sided | ring bar segments |
| `card` | Unlit, Transparent | card bodies, glyphs, plaque |
| `textMat` | Text material | all `Component.Text` labels |

`baseColor` / `textFill.color` are set at runtime from the track palette — no
per-track material work is needed.

## 3. Wire the controller

Add `OrbitSessionController` to `Orbit Stage` and connect the inputs exactly
as listed in `orbit-scene.manifest.json` (`ringRoot`, `cardsRoot`,
`plaqueRoot`, the three materials, font, the Remote Service module, and
`dataUrl` = the Pages URL of `data/session.json`).

## 4. Remote Service

Project Settings → **Remote Service**: create module `orbit-data`, allow-list
the host serving the web companion (e.g. `<user>.github.io`). The data JSON is
`soundcraft-orbit/session@1`, generated by `tools/build_data.py` — the same
file the web page uses, so the Lens and the desktop preview can never drift.

## 5. Preview captures (the evidence to attach)

In Lens Studio **Preview** (Spectacles device simulator), capture:

1. **Ambient stage** — the whole stage; confirm ring left, arc of 6 cards,
   plaque below ring, nothing clipped at the preview FOV boundary.
2. **FOV-crop check** — enable the device preview overlay; confirm all
   essential content sits inside ~51° horizontal at 1.5 m (the web
   companion's dashed FOV frame is the reference for what should survive).
3. **Inspect state** — gaze + pinch a card; capture the pulled-forward card.
4. **Live update** — rebuild the session (`tools/build_data.py` after a new
   bounce) and capture the plaque/bar-strip updating in preview.

Each capture goes into `docs/evidence/` and the Paperclip issue.

## 6. Data refresh loop

```bash
# after changing the session in SoundCraft (or re-running the build):
python3 tools/build_data.py          # regenerates web/data/session.json
git add web/data/session.json && git commit -m "session: <what changed>" && git push
# Pages redeploys; Lens preview picks it up on next fetch
```

## 7. Known tuning points (first device run)

- `Component.Text` sizing is font-metric dependent: labels are authored in mm
  (`size = mm * 0.1 * 10`) — verify the 0.7° text floor with the preview
  ruler and adjust the constant in `TrackCard.label` once for the chosen font.
- Ring segments are authored as tangent quads; at 8 bars the chord error is
  < 1 mm — if the gap reads uneven on device, switch segments to
  `ArcComponent`-based meshes.
- Depth stagger 1450→1650 mm is tuned for the arc; keep ±0.1 m of it if you
  move the stage origin.
