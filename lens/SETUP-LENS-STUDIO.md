# Lens Studio assembly & preview plan (Snap Spectacles)

Lens Studio is a desktop authoring app (Windows/macOS); company build nodes are
Linux/arm64 and cannot run it. This project therefore ships **complete Lens
project sources** — scripts implementing the full IA geometry plus a
declarative scene manifest — and this guide, so the Lens assembles in
Lens Studio in about 10 minutes. The web companion (`web/`) renders the same
geometry and serves as the geometric preview of record until the Lens preview
is captured.

> Hackathon note (Devpost Learn "AR with SPECS"): the challenge format expects
> an AI coding agent to build the Lens. Feed the agent this directory
> (`lens/`) + `docs/AR-INFORMATION-ARCHITECTURE.md` — the scripts, the scene
> manifest, and the data URL are everything it needs.

## 0. Prerequisites (all on Arthur's macOS machine — Lens Studio does not run on the company's Linux/arm64 nodes)

- macOS 12+ with Lens Studio 5.10+ and Spectacles support: https://ar.snap.com/download (~1 GB download)
- This repo cloned locally: `git clone https://github.com/SonniaAI/soundcraft-orbit`
- Internet access — the Lens fetches its data live from the deployed companion:
  `https://sonniaai.github.io/soundcraft-orbit/web/data/session.json`
- For screen captures: macOS built-in recorder (⌘⇧5) or OBS. Total time budget: ~30 minutes.

## 1. Create the project

1. Lens Studio → **New Project** → *Spectacles* template.
2. Import `lens/Scripts/*.ts` (drag the folder into the **Assets** panel).
3. Create three empty SceneObjects under a root named `Orbit Stage`:
   `Ring`, `Cards`, `Plaque` (see `orbit-scene.manifest.json`).

## 2. Materials

| Name | Pass settings | Used for |
| --- | --- | --- |
| `seg` | Unlit, Opaque, Double-Sided | ring bar segments |
| `card` | Unlit, Transparent | card bodies, glyphs, plaque |
| `textMat` | Text material | all `Component.Text` labels |

`baseColor` / `textFill.color` are set at runtime from the track palette — no
per-track material work is needed.

## 3. Wire the controller

Add `OrbitSessionController` to `Orbit Stage` and connect the inputs exactly
as listed in `orbit-scene.manifest.json` (`ringRoot`, `cardsRoot`,
`plaqueRoot`, the three materials, font, the Remote Service module, and
`dataUrl` = the Pages URL of `data/session.json`).

## 4. Remote Service

Project Settings → **Remote Service**: create module `orbit-data`, allow-list
the host serving the web companion (e.g. `<user>.github.io`). The data JSON is
`soundcraft-orbit/session@1`, generated by `tools/build_data.py` — the same
file the web page uses, so the Lens and the desktop preview can never drift.

## 5. Preview captures (the evidence to attach — exact runbook)

Everything below happens in Lens Studio's **Preview** panel with the Spectacles
device simulator. Set the preview device to **Spectacles** (not phone) so the
FOV matches the glasses. Capture these five artifacts, in order, and drop them
into `docs/evidence/` with these exact names:

| # | Capture | File name | How |
| --- | --- | --- | --- |
| 1 | Ambient stage | `lens-preview-stage.png` | Preview ▸ camera icon (screenshot). Frame the whole stage: ring left, arc of 6 cards, plaque below the ring. Nothing essential clipped. |
| 2 | FOV-crop check | `lens-preview-fov.png` | Enable the device preview overlay (Preview ▸ Show Device Bounds). Everything essential must sit inside ~51° horizontal at 1.5 m — compare against the dashed frame in `web-stage-fov-overlay.png`. |
| 3 | Inspect state | `lens-preview-inspect.png` | Gaze at the Lead card + pinch (or click in preview), hold the pulled-forward card, screenshot: waveform, clip list, insert chain visible. |
| 4 | Live update, before | `lens-live-before.png` | With the preview running and connected to the live `dataUrl`, screenshot the plaque (LUFS figure legible). |
| 5 | Live update, after | `lens-live-after.png` | Run `python3 tools/live_change.py` on any machine with the repo (it edits the session, bounces, stores the engine receipt), wait ~10 s for the JSON the Lens fetches to update, then screenshot again: the plaque shows a new LUFS figure and bar 8 dims on the ring. |

Plus one **video**: `lens-preview-demo.mp4` (30–60 s). ⌘⇧5 ▸ Record Selected
Region over the Preview panel, then in one take: show the ambient stage (5 s) →
turn your head slightly to show the stage stays anchored in space (5 s) → gaze
+ pinch the Lead card for the inspect pull (10 s) → dismiss (5 s) → run the
live change and hold on the plaque while the LUFS figure and ring update
(15 s). 1080p minimum, no narration needed (the Devpost video covers narration).

If a capture fails, do not retake more than twice — note what failed in the PR
and move on; the web-companion equivalents below are the accepted fallback set.

### Web-companion equivalents (pre-captured, same AR geometry)

The web companion renders the *same* millimetre geometry at the same 1.5 m
depth, with the true-to-angle 51°×30° FOV overlay dimming anything the glasses
would not show. These pre-captured equivalents stand in for each Lens capture
until (or instead of) the Lens Studio run:

| Lens capture | Web equivalent (committed) | Same geometry because |
| --- | --- | --- |
| Ambient stage | `web-stage-fov-overlay.png` | identical mm layout table; FOV overlay on |
| FOV-crop check | `web-stage-fov-overlay.png` | the dashed frame IS the 51°×30° window at 1.5 m |
| Inspect state | `web-inspect-lead.png` | same card pulled forward → focus panel with waveform/clips/inserts |
| Playing / playhead | `web-playing-bar3.png` | same ring playhead needle + active bar cell |
| Live update before/after | `live-bridge-before.png` / `live-bridge-after.png` | same ring segments + card mini-grids + bounce plaque, driven by the real bridge |

Each web equivalent is produced by the documented commands (see
`docs/evidence/README.md` for the exact receipts), so reviewers can reproduce
them without Lens Studio.

## 6. Data refresh loop

```bash
# make a REAL change to the session (edit + bounce + engine receipt), then:
python3 tools/build_data.py          # regenerates web/data/session.json
git add web/data/session.json receipts/ && git commit -m "session: <what changed>" && git push
# Pages redeploys; Lens preview picks it up on next fetch
```

`tools/live_change.py` does the whole change in one step (and `--restore`
returns the committed first-light state): it trims the Lead clip out of bar 8,
pushes Lead/Bass +3 dB, bounces, and stores the verbatim engine receipt as
`receipts/first-light-live.json` — the same flow the web bridge demonstrates.

## 7. Known tuning points (first device run)

- `Component.Text` sizing is font-metric dependent: labels are authored in mm
  (`size = mm * 0.1 * 10`) — verify the 0.7° text floor with the preview
  ruler and adjust the constant in `TrackCard.label` once for the chosen font.
- Ring segments are authored as tangent quads; at 8 bars the chord error is
  < 1 mm — if the gap reads uneven on device, switch segments to
  `ArcComponent`-based meshes.
- Depth stagger 1450→1650 mm is tuned for the arc; keep ±0.1 m of it if you
  move the stage origin.
